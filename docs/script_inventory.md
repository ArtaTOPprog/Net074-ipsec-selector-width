## Цепочка вызовов

1. `run.sh` → `gen.py`: разогрев, ручной старт monitor на ESR, отправка UDP, ручное копирование PCAP через TFTP.
2. `process_all.sh` → `analyze.py` для каждого PCAP → `stats.py` для таблицы и графика.
3. Отдельный ручной цикл `tcpdump` служит предварительной проверкой захватов.

Байты исходных gen.py, analyze.py, stats.py, run.sh и process_all.sh совпадают между присланными TAR и ZIP. Отображённый вывод согласуется с этими программами. Сам скриншот не доказывает точную версию всех строк файла; совпадение формата и цепочки вызовов — основание сопоставления для невидимых вызовов.

## Цикл на рисунке 15

Из папки с каталогом pcap:

```bash
for f in pcap/S3-*_esr1.pcap; do
  e=$(tcpdump -nr "$f" esp 2>/dev/null | wc -l)
  p=$(tcpdump -nr "$f" udp port 50074 2>/dev/null | wc -l)
  echo "$f ESP=$e открыто=$p"
done
```

Это воспроизведение ручного подсчёта со снимка. Фильтр `esp` не ограничивает направление, поэтому его результат 1004–1010 в S3 нельзя подставлять вместо 1000 исходящих тестовых пакетов. Причину конкретного лишнего ESP-пакета надо проверять по полям захвата; общий фильтр сам её не устанавливает.

## Что было добавлено при предыдущей доработке

`scripts/audit_legacy.py`, `scripts/pcapio.py`, `scripts/check_reference.py` — новый строгий повторный разбор исходной серии, необходимый для исправленных результатов статьи. Он не запускался на показанных старых скриншотах.

`traffic_v2.py`, `validate_v2.py`, `schedule.py`, `score_audit.py`, `capture.sh` — средства ещё не выполненных дополнительных испытаний. Теперь они вынесены в `extensions/`. Они не заменяют run.sh, gen.py, analyze.py, process_all.sh и stats.py.

Предыдущий архив был неполон как копия исходного рабочего процесса: четыре из пяти имён отсутствовали. Это исправлено. Восстановленные файлы имеют описанные изменения безопасности, путей и интерпретации метрик; история изменений содержится в [script_provenance.csv](script_provenance.csv).
