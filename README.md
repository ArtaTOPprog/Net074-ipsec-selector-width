# NET074: эксперимент с селекторами IPsec

Авторы: Муфахаров Артур Марселевич и Сафиуллин Ярослав Александрович, КЕ-25-02, РГУ нефти и газа (НИУ) имени И. М. Губкина.

В этой версии восстановлены пять скриптов рабочего процесса, показанного в исходном отчёте Ubuntu. Новые средства исследования отделены от фактически использованных программ.

## Какие файлы нужны

| Папка | Назначение |
| --- | --- |
| `experiment/` | `run.sh`, `gen.py`, `process_all.sh`, `analyze.py`, `stats.py`: рабочая цепочка исходного эксперимента |
| `data/legacy/` | 45 исходных PCAP, журнал `gt.csv` и калибровка `calib.json` |
| `scripts/` | Исправленный повторный анализ для статьи: PCAP, ICMP, пакетные ID и сверка результатов |
| `results/reference/` | Шесть проверенных файлов результатов повторного анализа |
| `docs/` | Статья, эксперимент, протокол и сверка скриптов со скриншотами |
| `extensions/` | Необязательные инструменты будущих испытаний; на исходных скриншотах они не запускались |
| `tests/`, `.github/` | Проверка программ и workflow GitHub Actions |

`scripts/legacy_gen.py` — совместимый вход в тот же `experiment/gen.py`, чтобы команды из ранее подготовленного отчёта оставались рабочими. Вторая копия генератора не хранится.

## Скрипты со скриншотов

```bash
cd experiment
chmod +x run.sh process_all.sh
./run.sh esr S1 1
./run.sh esr S2 1
./run.sh esr S3 1
./process_all.sh
```

Первые три команды отправляют трафик и требуют собранного учебного стенда. Их выполняют по одному после соответствующей настройки селектора на обоих шлюзах. `run.sh` сам не меняет селектор. Сохраняется именно использованный в работе вариант Eltex ESR на площадке A; варианты с MikroTik/Cisco на A в эту проверенную ветвь не включены.

По умолчанию новые захваты и журнал пишутся в `results/local/acquisition`, отдельно от 45 архивных файлов. Для новой серии укажите новый `WORK_DIR`:

```bash
WORK_DIR="$HOME/net074-session-02" ./run.sh esr S1 1
```

Параметры `RATE` (по умолчанию 200), `TFTP_DIR` (по умолчанию `/srv/tftp`) и `PYTHON` можно задать через окружение. Скрипт копирует только PCAP текущего прогона и не перезаписывает существующий файл. Перед новым захватом одноимённый файл в TFTP нужно самостоятельно перенести из общей папки.

`./process_all.sh` запускает историческую цепочку `analyze.py` → `stats.py` по сохранённым 45 PCAP, без отправки трафика и перемещения исходников. Результат: `results/local/historical/results.csv`, `summary.csv`, `summary.md`; график `fig_selector.png` создаётся, если установлен matplotlib. Python 3.10+ достаточен для CSV/Markdown; для графика нужен matplotlib, scipy необязателен при n=15. Для повторной обработки выберите новую выходную папку:

```bash
./process_all.sh ../data/legacy ../results/local/historical-02
```

Эта цепочка сохранена для сопоставления с исходной работой. Её ESP-классы основаны на калиброванных длинах, ICMP она не разбирает. Подпись S3 исправлена на `192.0.0.0/2`; агрегатный недосчёт на WAN больше не называется потерями приложений. Оценка классов по одному счётчику SA отключена как недостаточно обоснованная.

## Повторный анализ для исправленной статьи

Из корня репозитория, только стандартная библиотека Python:

```bash
python3 scripts/audit_legacy.py --root data/legacy --out results/local/legacy
python3 scripts/check_reference.py --actual results/local/legacy --expected results/reference
python3 -m unittest discover -s tests -p test_suite.py -v
```

Ожидаются 45 прогонов, 225 агрегатных сравнений без расхождений, проверка 13 600 открытых UDP и совпадение 6 файлов результатов. Проверка программ включает 9 тестов и обмен UDP на 127.0.0.1. Она не является новым измерением VPN.

## Публикация в GitHub

Распакуйте архив и откройте папку с README. Создайте пустой репозиторий GitHub, затем:

```bash
git init
git add .
git commit -m "Add NET074 experiment and reproducible audit"
git branch -M main
git remote add origin URL_ВАШЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

В Git отправляется содержимое папки, включая `.gitignore`, `.gitattributes` и `.github`. Workflow подготовлен для Ubuntu/Windows; его запуск в пользовательском репозитории ещё не выполнялся. Лицензия от имени авторов автоматически не назначается.
