# NET074: влияние ширины селектора Policy-based VPN на риск избыточного шифрования

Материалы исследования NET25-038 / NET-074: описание лабораторного стенда, скрипты эксперимента, захваты трафика и воспроизводимый анализ результатов.

В работе сравниваются три варианта адресного селектора IPsec. Цель исследования: определить, как расширение селектора влияет на включение трафика в туннель и шифрование потоков сверх заданной политики защиты. Дополнительно анализируются открытые ICMP-ошибки и содержащиеся в них заголовки тестовых пакетов.

## Сценарии эксперимента

Источник тестового UDP-трафика: `192.168.10.100`. Политика требует защищать обмен с узлом P (`192.168.20.10`, UDP-порт `50074`). Генератор также отправляет пакеты на назначения N1, N2, E1 и E2, чтобы выявлять включение в туннель потоков за пределами этой политики.

| Сценарий | Локальный адрес на ESR | Удалённый диапазон на ESR | Охват тестовых назначений |
| --- | --- | --- | --- |
| S1 | `192.168.10.100/32` | `192.168.20.10/32` | P |
| S2 | `192.168.10.100/32` | `192.168.20.0/24` | P, N1, N2 |
| S3 | `192.168.10.100/32` | `192.0.0.0/2` | P, N1, N2, E1, E2 |

На стороне Cisco адресные условия зеркальны. Точные значения приведены в [selectors.csv](configs/selectors.csv), требования к защите заданы отдельно в [policy.json](configs/policy.json).

Опубликованная серия включает **45 прогонов: по 15 для каждого селектора**, по 1000 тестовых UDP-пакетов на прогон. Захват выполнен на WAN-интерфейсе ESR-A.

## Быстрый старт

Для обработки сохранённых данных достаточно **Python 3.10+ и стандартной библиотеки**. Доступ к лабораторному оборудованию не требуется.

Склонируйте репозиторий и перейдите в его корень:

```bash
git clone https://github.com/ArtaTOPprog/Net074-ipsec-selector-width.git
cd Net074-ipsec-selector-width
```

Выполните анализ и сравнение с контрольными результатами:

```bash
python scripts/audit_legacy.py --root data/legacy --out results/local/legacy
python scripts/check_reference.py --actual results/local/legacy --expected results/reference
```

В Linux при необходимости используйте `python3` вместо `python`. Команды обработки подходят и для PowerShell.

Результаты появятся в `results/local/legacy/`. Ожидаемый итог: 45 обработанных прогонов, 225 агрегатных сравнений без расхождений, проверка 13 600 открытых тестовых UDP-пакетов и совпадение шести файлов с `results/reference/`.

Для запуска автоматических проверок:

```bash
python -m unittest discover -s tests -p test_suite.py -v
```

Проверки включают локальный UDP-обмен на `127.0.0.1`. Этот же набор проверок и пересчёт данных выполняет GitHub Actions.

## Запуск на стенде

Для новых прогонов нужен настроенный учебный стенд с Eltex ESR на площадке A и Cisco на удалённой стороне, Bash, Python и доступный TFTP-каталог. Подготовка и параметры описаны в [документе эксперимента](docs/experiment.pdf) и [configs/README.md](configs/README.md).

Перед каждым прогоном настройте нужный селектор на обоих шлюзах и проверьте состояние SA. `run.sh` сопровождает захват и отправку трафика; селекторы на оборудовании задаются вручную.

Пример одного прогона S1:

```bash
cd experiment
bash run.sh esr S1 1
```

Аргументы: `esr`, селектор `S1` / `S2` / `S3`, номер прогона от `1` до `15`. Следуйте подсказкам скрипта для захвата на ESR и копирования PCAP по TFTP.

| Переменная окружения | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `WORK_DIR` | `results/local/acquisition` относительно корня проекта | Каталог захватов и журнала новой серии |
| `RATE` | `200` | Темп отправки, пакетов в секунду |
| `TFTP_DIR` | `/srv/tftp` | Каталог, в который ESR выгружает PCAP |
| `PYTHON` | `python3` | Команда запуска Python |

Для отдельной серии задайте новый `WORK_DIR`. Имя PCAP текущего прогона должно быть свободно и в рабочем каталоге, и в TFTP-каталоге.

### Агрегатная обработка

Из корня репозитория можно запустить цепочку `analyze.py` → `stats.py` по опубликованным данным:

```bash
bash experiment/process_all.sh
```

Выходные файлы: `results/local/historical/results.csv`, `summary.csv` и `summary.md`. Если установлен `matplotlib`, дополнительно создаётся `fig_selector.png`. Для повторного запуска выберите новый выходной каталог:

```bash
bash experiment/process_all.sh data/legacy results/local/historical-02
```

Эта цепочка рассчитывает агрегатные показатели по калиброванным длинам ESP. Для разбора ICMP и проверки идентификаторов открытых пакетов используйте `scripts/audit_legacy.py` из раздела [«Быстрый старт»](#быстрый-старт).

Инструменты для дополнительных серий и проверки доставки описаны в [extensions/README.md](extensions/README.md) и [протоколе испытаний](docs/reproducibility.md).

## Границы исследования

- Наблюдения относятся к опубликованной серии и точке захвата WAN ESR-A. Отдельных журналов приёмника и захватов до шифрования и после расшифрования в этой серии нет.
- Классы ESP определяются по различающимся калиброванным длинам. Проверки SPI и Sequence Number относятся к внешним заголовкам ESP.
- Данные WAN не подтверждают сквозную доставку приложению, нулевые потери или доступность внешней службы. CPU и предельная производительность VPN в этой серии не измерялись.
- Инструменты в `extensions/` предназначены для дополнительных испытаний. Их наличие не означает, что такие испытания уже проведены.
